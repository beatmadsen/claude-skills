Hand-drawn architecture sketch of fun-ci, a Ruby gem that runs CI on your own machine. A commit's run: you commit, the post-commit hook passes the commit and branch to fun-ci trigger and returns at once, and the run goes on in the background in a git worktree checked out at that commit. There lint and build run side by side within 30 seconds each, then the fast suite, within 10 seconds, and the slow suite, within 5 minutes, side by side; a stage over its budget is killed. Results go to one SQLite database shared by every project on the machine. Two readers: you watch fun-ci console on a second screen, and your agent runs fun-ci wait and fun-ci why. Who decides a push: the pre-push hook runs fun-ci wait --need fast for each commit pushed, which blocks until the run is decided; a pass lets the push go, a failure or an overrun stops it, and a project not set up for fun-ci pushes without CI.
